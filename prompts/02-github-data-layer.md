# PROMPT 02 — GitHub-as-database (read layer), schemas, seed content, image proxy

**Attach:** nothing.
**Prerequisite:** CONTEXT BLOCK pasted; prompt 01 done.

## Goal
Make the private GitHub repo `gkds` (branch `data`) act as the website's database for reading, with zod-validated content, a complete seed fallback, an image proxy for the private repo, and a revalidation endpoint. Writing comes in prompt 10.

## 1. Schemas (`lib/validators/`)
Implement zod schemas + inferred types for **exactly** the data model in CONTEXT BLOCK §8: `site`, `home`, `about`, `courses`, `gallery`, `reviews`, `pendingReview`, `adminConfig` (`{hash, salt, updatedAt, sessionVersion}`). Rules:
- Strings trimmed with sensible max lengths (titles ≤ 120, paragraphs ≤ 1500, alt ≤ 200).
- `phones` min 1; `whatsapp` digits only 10–15 chars; `email` valid; URLs must be `https://` (map embed must be a `google.com/maps` URL, validated by a refinement function `isGoogleMapsEmbed`).
- `rating` between 1 and 5 in 0.5 steps; `date`/`createdAt` ISO strings; `slug` regex `^[a-z0-9]+(?:-[a-z0-9]+)*$`; ids are non-empty strings (use `nanoid`-like helper `newId()` in `lib/utils`).
- Include the fields `Site.callCardText` (seed: "Speak to us for course details, timings and admission information. We're happy to help!") and `Reviews.acceptSubmissions` (default true) from CONTEXT BLOCK §8.
- Export `contentSchemas` map `{ site, home, about, courses, gallery, reviews }` and `contentNames` const tuple (used by admin APIs).
- Export helper `parseContent(name, data)` returning `{ok, data}|{ok:false, errors: Record<path,message>}` (for field-level admin errors).

## 2. GitHub client (`lib/github.ts`, `server-only`)
- Uses `fetch` only (no Octokit). Base `https://api.github.com/repos/${GITHUB_OWNER}/${GITHUB_REPO}`; headers `Authorization: Bearer ${GITHUB_TOKEN}`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, user-agent `gkds-site`.
- `isGithubConfigured()` returns false if any of token/owner/repo is missing.
- `readJson<T>(path, {tags, revalidate})`: `GET /contents/{path}?ref={GITHUB_BRANCH}` with `Accept: application/vnd.github.raw+json`; Next cache options `{ next: { revalidate: 3600, tags: ['content', `content:${name}`] } }`; 8-second timeout via `AbortController`; one retry on network error or 5xx; typed errors (`GithubNotFoundError`, `GithubRateLimitError`, `GithubAuthError`, `GithubError`).
- `readRaw(path)` returns `{ buffer, contentType }` for images (use `Accept: application/vnd.github.raw+json`, binary arrayBuffer). Files > 1 MB: GitHub raw media type supports up to 100 MB, so use raw accept header — do not use base64 content API for reading.
- `listDir(path)` → `[{name, path, type, sha, size}]`.
- Never log the token. Never import this file from a client component (`import 'server-only'`).

## 3. Content access (`lib/content/index.ts`)
Functions `getSite()`, `getHome()`, `getAbout()`, `getCourses()`, `getGallery()`, `getReviews()`, plus helpers `getPublishedCourses()`, `getPublishedGallery()`, `getPublishedReviews()`, `getFeaturedReviews(limit = 3)`, `getReviewStats()` (uses `site.stats` when `reviews.summaryMode==='manual'`, else computes average rating, count and recommend% = share of reviews ≥ 4 stars).
Each getter: if GitHub configured → `readJson` → zod-validate → return; on ANY failure (not configured, 404, invalid JSON/schema, network, rate limit) → `console.warn` (server) and return the validated seed from `content-seed/<name>.json`. Wrap getters in React `cache()`. The site must build and run with **no env vars at all**.
Also export `getAllCourseOptions()` (used by header dropdown) and type exports.

## 5. Image proxy (`app/api/media/[...path]/route.ts`)
GET only, `runtime = 'nodejs'`. Validate: path joined must start with `media/`; reject `..`, backslashes, empty segments, null bytes; extension whitelist `webp|jpg|jpeg|png|svg|avif|gif`. Fetch via `readRaw`; return the bytes with correct `Content-Type`, `Cache-Control: public, max-age=31536000, s-maxage=31536000, immutable`, `X-Content-Type-Options: nosniff`; for SVG add `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`. 404 on miss (cache 60s), 502 on other errors. Helper `mediaUrl(path)` in `lib/media.ts`: if path starts with `media/` → `/api/media/${path.slice(6)}`-style mapping (choose one consistent mapping and document it), if it starts with `/` or `http` → unchanged. Configure `next.config` `images.localPatterns` / `qualities` so `next/image` works with `/api/media/**` and `/assets/placeholders/**`.

## 6. Revalidation endpoint
`app/api/revalidate/route.ts` (POST): requires header `x-revalidate-secret` equal to `REVALIDATE_SECRET` (timing-safe); optional JSON `{tag}` else `content`; calls `revalidateTag`; returns `{revalidated:true}`. 401 otherwise.

## 7. Docs & scripts
- `docs/DATA_REPO.md`: how to create the private repo `gkds`, how to create the orphan `data` branch (`git checkout --orphan data`, `git rm -rf .`, commit, push, return to `main`), folder structure, fine-grained token scopes (Contents R/W, Metadata R, only this repo), and `vercel.json` snippet `{"git":{"deploymentEnabled":{"data":false}}}` (create `vercel.json` now with that plus `"regions":["bom1"]`).
- `scripts/push-seed.mjs`: reads `content-seed/*.json` and uploads them to `content/` on the `data` branch via the GitHub Contents API (creating or updating with sha), logs each result; refuses to run if env vars are missing.
- Tests (vitest): schema validation (valid + invalid cases), fallback behaviour when GitHub is unconfigured/404/invalid JSON, `mediaUrl` mapping, path-traversal rejection in the proxy, `getReviewStats` math (auto vs manual).
